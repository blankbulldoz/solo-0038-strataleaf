# 单机灾备环境说明

本文描述 StrataLeaf 嵌入式部署（Python 服务进程内使用 `strataleaf.Database`）在**单机**范围内的灾备接收环境：哪些目录、哪些身份、哪些前置条件必须成立，以及演练工具 `ops.dr` 覆盖与不覆盖的范围。

## 1. 角色与目录

| 角色 | 典型路径 | 说明 |
| --- | --- | --- |
| 主库 | `/srv/app/service.db` | 业务进程持续写入的活动 SQLite WAL 文件。**唯一事实来源。** |
| 备份仓 | `/srv/backups/` | 存放 `archives.backup` 发布的归档及其 `<归档名>.manifest.json`。 |
| 恢复区 | `/srv/recovery/` | 与主库**物理隔离**的目录；恢复出的新主库或副本落在这里。 |
| 证据区 | `/srv/recovery/evidence/` | 演练报告、`artifacts.sha256`。 |

隔离要求：恢复目录不得与主库目录相同或位于同一被并发写入的挂载点下；恢复一律写**新的未占用路径**。工具在 `restore_and_verify` 后会断言恢复路径不等于主库路径。

## 2. 必须成立的系统前提

1. **Python 3.11+**，仅标准库 `sqlite3`，无网络依赖。
2. 备份、恢复、接收都在**同一主机**、本地或可靠块设备上；**不支持共享网络盘和多主写入**（库的 README 已固定该边界）。
3. 主库只有一个写入进程；跨进程读依赖 SQLite 锁，忙超时由连接的 `timeout` 控制。
4. 恢复目录可写且空间足够容纳一份完整数据库；备份仓与主库**不同磁盘**才谈得上介质级灾备（本工具不做跨盘校验）。
5. 接收方启动前，主库保留水位（`floor`）不得越过接收方所需修订——否则只能重新引导，不能增量接收。

## 3. 身份与凭据边界

- 主库恢复（`Archives.restore(..., follower=False)`）：**更换** `database_id` 与游标签名密钥，清空 pins/consumers，保留文档版本。恢复后**旧游标、旧消费者与旧确认位置全部失效**，调用方必须重新注册。
- 副本恢复（`follower=True`）：**保留**上游 `database_id` 并绑定 `upstream`；只接收同一上游、连续的提交包。
- 基线**不提供**副本提升为主库的接口，也不提供双向复制。所谓「切换」= 在恢复区恢复出一个新主库并让业务改连，旧主库必须停止写入。

## 4. 恢复点（RPO）与可用性（RTO）边界

| 指标 | 含义 | 本方案给出的边界 |
| --- | --- | --- |
| RPO | 可丢失的已提交写入 | = 备份时刻到灾难时刻之间、且未被后续接收副本覆盖的提交。备份用在线备份 API，**不会**丢失备份快照内的写；备份间隔决定上限。 |
| RTO | 从决定恢复到可服务的时间 | = 恢复 <归档> + 全量事实核对 + （可选）接收后续提交。随数据量线性增长，本工具在报告里实测记录。 |
| 数据完整性 | 恢复后可读且与归档一致 | 由 `inspect`/指纹/索引投影/目录/提交连续性共同核对，**不以 head 相等代替**。 |
| 目录身份 | 恢复出来的是「谁」 | 新主库身份必须已轮换；副本身份必须与上游一致。 |

**明确不覆盖**：多主机共识、跨地域复制、备份介质与主机同时损毁、源 floor 已越过接收方修订且无新备份时的时间点恢复、副本自动提升。

## 5. 演练工具能证明什么

`python3 -m ops.dr drill --root <新目录>` 在真实文件、真实库 API 上依次完成：

- 主库**持续写入期间**用在线备份 API 取得归档，发布前校验摘要，并断言归档**不依赖非空 WAL 侧车**（自包含）；
- 把归档恢复到隔离目录，逐项核对：文档内容摘要、文档数、模式、索引**定义与物化投影重算**、目录 epoch、提交连续性、SQLite 完整性、外键；
- 把恢复件作为副本绑定上游，**接收**备份之后产生、且仍在源保留范围内的提交；期间注入**接收中断**（分两段续传）、**重复包**与**被篡改包**；
- 注入**源历史已回收**：把源 floor 推过副本修订，证明增量接收被拒绝（`SnapshotTooOld`），随后用**新备份重新引导**副本并追上；
- 注入**备份失败**：存储不可写时全部尝试失败且不发布归档；目标已被占用时不覆盖、改用新名字成功；
- 直接对照**裸拷贝主文件**：说明为何不可作为备份（可读性/头部/无清单/带活动侧车）；
- 产出 `evidence/drill-report.json|md` 与 `artifacts.sha256`，可用 `verify-evidence` 独立复算。

工具**不**修改 `strataleaf/` 任何文件；所有读写都经公开 API 或只读 URI。

## 6. 端口、账号与权限

本方案无网络端口、无服务账号。运行者需要：对备份仓/恢复目录的读写权限；对主库的**读**权限（备份 API 需要打开主库）；不要求对主库目录写权限——但不要在该目录手工落文件。演练中的「存储不可写」通过目录权限位模拟，结束后恢复权限。
